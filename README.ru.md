# Cropper

[English](README.md) · **Русский**

Кадрирование картинок под релиз одной страницей: выбираете размер холста,
ловите кадр, забираете файл в полном разрешении. Без сборки, без зависимостей,
без сервера — откройте `index.html` в браузере, работает офлайн.

![Cropper](docs/screenshot.png)

## Быстрый старт

```bash
git clone https://github.com/<вы>/cropper.git
cd cropper
xdg-open index.html        # macOS: open index.html
```

Это вся установка. Дальше:

1. Перетащите картинку на холст (или нажмите на него и выберите файл).
2. Возьмите шаблон — обложка, карточка артиста, сторис, баннер, аватар — или впишите свой размер.
3. Перетаскивание двигает, колесо приближает, двойной клик вписывает.
4. Выберите формат, посмотрите на заметку о качестве, нажмите **Скачать**.

## Что умеет

- **Шаблоны холста** под размеры, которые просят дистрибьюторы и площадки, плюс любой свой размер.
- **Честное кадрирование.** Мышь работает по самой картинке; превью уменьшено,
  а экспорт всегда режется из исходного файла в полном разрешении.
- **Сторож качества.** Панель показывает, сколько пикселей оригинала попадает в
  кадр, и предупреждает, когда картинку начинает тянуть вверх и она поплывёт.
- **Подгонка холста под картинку** — тремя способами: по видимой части, по всей
  картинке целиком или пропорционально текущей длинной стороне.
- **Сетка третей** поверх кадра.
- **JPEG / PNG / WEBP** с настраиваемым качеством и редактируемым именем файла.
- **Языки и темы** — русский и английский в комплекте, свои подключаются
  файлом прямо в интерфейсе (⚙ в шапке) или кладутся рядом с `index.html`.

Открытые блоки, размер холста, формат, язык и тема запоминаются между
сессиями (`localStorage`).

## Клавиши

| Клавиша | Действие |
| --- | --- |
| `0` | вписать картинку в холст целиком |
| `1` | заполнить холст |
| двойной клик | вписать |

## Из чего состоит

```
index.html                  разметка и порядок подключения файлов
config.js                   настройки: язык, тема, блоки, шаблоны, форматы
main.js                     композиционный корень: настройки → модули
css/app.css                 блоки и размеры — ни одного цвета, всё через токены
themes/{dark,light}.css     темы: полный список токенов
lang/{ru,en}.js             словари
kernel/                     контейнер, шина событий, сборка
Core/Geometry/Frame/        математика кадрирования — чистая, без DOM
Core/Storage/{KeyValue,Files}/   порты к localStorage и файлам
Modules/Canvas/Size/        размер холста
Modules/Image/Frame/        кадр: загрузка, масштаб, положение
Modules/Export/Save/        формат, качество, сохранение файла
Modules/Shared/Panel/       панель и её блоки
Modules/Shared/Preferences/ язык и тема
scripts/arch-check.mjs      проверка границ модулей
docs/                       скриншоты
```

Стили по БЭМ: `блок`, `блок__элемент`, `блок--модификатор`. Каждое правило
начинается с класса, поэтому разметку и стили можно читать рядом.

## Как устроен код

Модульный монолит вертикальными слоями: каждый модуль — одна бизнес-функция
со своими данными, действиями и точками входа.

- **Бизнес-логика живёт в `Actions/`**: один класс — одна операция, один
  публичный `run()`. Точка входа (`Ui/Controllers/`) только собирает DTO и
  зовёт одно действие.
- **Модули не лезут друг к другу внутрь.** Наружу открыты только
  `Contracts/`, `Events/`, `DTO/`, `VO/`, `Enums/`, `Exceptions/`. Синхронный
  вызов — через контракт (так «Кадр» просит «Размер холста» подогнаться под
  картинку), уведомление — через событие (так «Экспорт» узнаёт, что холст
  изменился, и предлагает новое имя файла).
- **Общее без точек входа — в `Core/`**: геометрия кадра и порты к хранилищу.
  Core ничего не знает о модулях.
- **Хранилище — только через репозиторий**, внешнее — только через шлюз.
  Каждый модуль пишет свой ключ в `localStorage`, чужие не трогает.
- **DTO, VO, события и исключения неизменяемы** — заморожены в конструкторе.

Правила взяты из скилла `modular-monolith`; отступления, которых потребовала
браузерная среда, перечислены в [AGENTS.md](AGENTS.md).

Границы проверяются без сборки и зависимостей:

```bash
node scripts/arch-check.mjs
```

Проверка ловит обращение к внутренностям чужого модуля, зависимость вверх по
слоям, действие с двумя публичными методами, незамороженный DTO и
несоответствие имени файла роли.

## Свои языки

Язык переключается в ⚙ в шапке. Там же две кнопки:

- **Файл…** — подключить свой словарь с диска, `.json` или `.js`;
- **Шаблон** — скачать текущий словарь целиком, чтобы перевести его.

Обычный порядок: скачали шаблон → перевели строки → загрузили обратно.
Словарь остаётся в браузере и подхватывается при следующем запуске.

Чтобы язык был в наборе с самого начала, положите файл в `lang/` и
подключите рядом с остальными в `index.html`:

```html
<script src="lang/es.js"></script>
```

Формат словаря — один вызов:

```js
App.lang({
  code: 'es',
  name: 'Español',
  dir: 'ltr',                 // 'rtl' для арабского или иврита
  strings: { appTitle: 'Recorte', load: 'Cargar', save: 'Descargar' }
});
```

Тот же объект без обёртки — готовый `.json` для загрузки через ⚙.
Ключи, которых в переводе нет, берутся из запасного языка (`fallbackLang`
в `config.js`), поэтому неполный перевод ничего не ломает.

## Свои темы

Тема — это файл с токенами и больше ничем: `themes/dark.css` показывает
весь набор с пояснениями. Токены одинаковые у Cropper и Clipper, так что
тему можно переносить между ними как есть.

Файл, загруженный через ⚙ → Тема → Файл…, **дополняет** выбранную тему, а не
заменяет её — достаточно переопределить несколько токенов:

```css
:root {
  --acc: #2f7fbf;
  --bg: #eef2f6;
}
```

Готовую тему удобно положить рядом и объявить в `config.js`:

```js
App.theme({ id: 'sand', name: 'Песок', href: 'themes/sand.css' });
```

Разметка и размеры живут в `css/app.css`, цветов там нет вообще. Классы по
БЭМ, поэтому из своего файла легко переопределить и отдельный блок:
`.preset--on { … }`.

## Настройки (config.js)

| Ключ | Что задаёт |
| --- | --- |
| `lang`, `fallbackLang` | язык при первом запуске (`auto` — по браузеру) и запасной |
| `theme` | тема при первом запуске |
| `blocks.order`, `.hidden`, `.open` | порядок блоков панели, что спрятать, что раскрыть |
| `presets`, `preset` | шаблоны холста и выбранный по умолчанию |
| `formats`, `quality` | форматы экспорта и качество JPEG/WEBP |
| `matte` | чем заливаются поля при экспорте в JPEG |
| `grid` | сетка третей |
| `outNamePattern` | шаблон имени файла, `{w}`, `{h}`, `{ext}` |
| `previewMax` | потолок внутреннего разрешения превью |

Выбор пользователя всегда сильнее: язык, тема и состояние панели остаются в
браузере. Кнопка **Сбросить своё** в ⚙ возвращает всё к `config.js`.

## Тесты

Зависимостей нет, `npm install` не нужен — всё на встроенных инструментах:

```bash
npm test          # 160 модульных тестов, встроенный раннер node --test
npm run arch      # проверка границ модулей
npm run smoke     # прогон в настоящем браузере
npm run check     # границы + тесты
```

Тесты лежат внутри модулей, рядом с кодом:

```
Core/Geometry/Frame/Tests/Unit/          математика кадрирования
Core/Storage/KeyValue/Tests/             контракт хранилища и его реализации
Modules/<Модуль>/Tests/Unit/             чистая логика
Modules/<Модуль>/Tests/Feature/          действия целиком, на заглушках
Modules/<Модуль>/Tests/Contracts/        контрактные тесты публичной поверхности
Modules/<Модуль>/Tests/Doubles/          заглушки, опубликованные для чужих тестов
```

Три вещи, ради которых это устроено именно так:

- **Загрузчик вместо сборки.** `scripts/test-loader.mjs` читает порядок
  скриптов прямо из `index.html` и выполняет их в одном контексте `node:vm` —
  ровно как браузер. Поэтому тесты гоняют тот же код, что открывается с диска,
  без бандлера и без `import`.
- **Контрактные тесты.** Модуль публикует тест своего контракта; его проходят
  и настоящее действие, и заглушка, которой пользуется чужой модуль. Заглушка
  «Размера холста» в тестах «Кадра» проверяется тем же тестом, что и оригинал, —
  иначе зелёный тест на заглушке ничего не значил бы.
- **Браузер отдельно.** `npm run smoke` открывает страницу в headless-браузере
  и проходит путь пользователя: перетащить картинку, выбрать шаблон, приблизить,
  подогнать холст, сохранить файл, переключить язык и тему. Это то, что нельзя
  проверить без DOM.

## Браузеры

Любой современный Chromium, Firefox или Safari. Для экспорта в WEBP нужен
браузер с `canvas.toBlob('image/webp')` — есть в Chromium, Firefox и Safari 17+.
